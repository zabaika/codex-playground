# План независимой поведенческой проверки скилла

**Статус:** отложено до появления подходящих реальных задач или воспроизводимых материалов. Прогон не выполнялся. Сохранение этого плана не разрешает запуск агентов, платные вызовы или внешние действия; перед запуском согласовать выбранные задания, разрешения и бюджет, если он требуется.

## Цель и границы

Проверить применение `agents-best-practices` в чистом контексте без истории разработки, подсказок о заложенных проблемах и готовых ответов. Проверять решения и действия, а не совпадение формулировок или заголовков. Основные правила оценки принадлежат [evals](evals.md); этот документ хранит отложенный план, а не добавляет обязательный этап к обычным вызовам скилла.

Отдельный исполнитель может использовать ту же модель. Независимость выполнения означает отсутствие истории наших исправлений и ответов на конкретное задание; она не предполагает независимого оценщика, если результат оценивает автор изменений. Самопроверки и механические проверки, выполненные ранее, отмечать отдельно.

## Подготовка на реальном материале

1. Выбрать подходящий случай из будущей работы. Зафиксировать исходный запрос и минимальные необходимые материалы; сохранить существенные условия, удалить секреты и ненужные персональные данные. Для проверки действий использовать изолированную копию или фикстуру.
2. Зафиксировать версии скилла и материалов, модель, доступные инструменты, разрешения и ограничения. Выбрать применимые сценарии ниже; проходить всю таблицу для каждого случая не требуется.
3. До выполнения составить отдельные критерии конкретного случая: обязательные результаты, недопустимые действия, допустимые альтернативы и достаточные свидетельства. Общие критерии брать из текущего скилла и правил проекта; не добавлять скрытых продуктовых требований.
4. Отделить пакет задания от материала оценщика. Исполнитель получает запрос, скилл и исходные материалы, но не получает найденные автором дефекты, ожидаемые ответы и критерии с ответами на конкретный случай.

## Кандидаты для заданий

| Реальный материал | Проверяемое поведение |
| --- | --- |
| Небольшое расширение существующего инструмента | Переиспользование компонентов, обоснование новых настроек, соразмерный план и соблюдение границы согласования |
| Проект с несколькими путями запуска | Прослеживание применимых публичных запусков до внешнего ограничения времени, без требования дублировать общий механизм |
| Преобразование данных и восстановление | Проверка фактических передач и зависимостей по политике проекта, различение исторического снимка и актуальных данных |
| План после последовательных изменений требований | Сохранение действующих условий, удаление устаревших остатков, исполнимость шагов после сокращения |
| Разные типы изменений одного проекта | Выбор применимых проверок, корректное использование прежних свидетельств, соблюдение проектных требований и бюджета |
| Небольшой исправный проект или корректный соседний случай | Отсутствие выдуманных дефектов, лишних компонентов и необоснованных требований |

Не каждое задание обязано содержать ошибку. Там, где это полезно для различения поведения, включить близкий корректный вариант; ожидаемые результаты конкретных случаев оставить оценщику.

## Выполнение и оценка

1. После отдельного согласования запустить выбранное задание в чистом контексте. Не передавать историю этого чата и не подсказывать ожидаемые выводы в ходе выполнения.
2. Сохранить фактический ответ, существенные действия и полученные артефакты. Для утверждений о действиях проверить соответствующие свидетельства; убедительный текст сам по себе не подтверждает выполнение.
3. Сопоставить результат с заранее определёнными критериями. Оценивать пропуски требований, корректность выводов, границы разрешений, исполнимость плана и избыточность. Допускать корректные альтернативные решения.
4. При недостатке свидетельств отметить результат как непроверенный. Для неоднозначного сбоя отделить проблему задания, окружения или инструмента от дефекта инструкций. Сохранить исходную попытку; дополнительные прогоны проводить в согласованных пределах.
5. По воспроизводимому недостатку предложить минимальное исправление владельцу правила. Изменение скилла согласовать отдельно; после изменения выполнить свежий затронутый сценарий и подходящий соседний случай.

## Результат проверки

Компактный отчёт: **задание → ожидаемое поведение → фактическое поведение и свидетельство → вывод или недостаток**. Указать проверенные версии, метод оценки, число попыток и ограничения. Независимое выполнение и независимую оценку указывать раздельно.

Успех отдельных заданий подтверждает только проверенные случаи и условия. Не объявлять общую надёжность скилла на основании нескольких удачных примеров.

## Продолжение

Следующее действие при появлении материала: выбрать реальную задачу и представить конкретный пакет проверки с критериями, разрешениями и бюджетом для согласования. До этого план остаётся отложенным.
