# Agents Best Practices — converted Codex package

Локальный Codex-скилл для проектирования, аудита, диагностики и корректировки ТЗ для агентных приложений и ограниченных LLM-workflow. Это инструкции и справочники; пакет не запускает службу, не подключает MCP, не регистрирует аккаунты и не отправляет сообщения.

## Использование

После установки вызывайте `$agents-best-practices`. Пример: «Используй $agents-best-practices для аудита восстановления Telegram-дайджеста после таймаута. Нужны наблюдаемые причины и минимальные изменения».

По умолчанию результат новой содержательной задачи — диагностика и предлагаемый план. Реализация начинается только после явного утверждения представленного плана; продолжение уже утверждённого плана не требует нового согласования каждого обратимого шага. Точная граница разрешений находится в [SKILL.md](SKILL.md#request-routing-and-implementation-gate). Простой вопрос о возможностях получает краткий ответ без исследования проекта.

Для доработки готового ТЗ используется [маршрут корректировки требований](references/harness-workflows.md#requirements-refinement-mode). При проектировании сначала выбирается [фиксированный workflow или агентный цикл](references/architecture.md#execution-shape-and-design-justification); новые компоненты и настройки обосновываются относительно существующих, а стартовые численные лимиты обозначаются как предложения, если они не измерены и не заданы внешним контрактом.

Для существенной многоэтапной реализации применяется [структура плана исполнения](references/harness-workflows.md#implementation-plan-structure): сначала сводятся действующие требования, затем проверяются исполнимость карточек и ранний сквозной сценарий. Общие инструкции задаются один раз; при сокращении плана проверяется сохранение смысла требований. Короткая диагностика и небольшая корректировка ТЗ сохраняют компактный формат; подробный контракт принадлежит справочнику, общие правила проекта — `RULEBOOK.md`.

После подготовки каждого результата, включая повторные правки, обязателен отдельный [финальный проход](references/harness-workflows.md#final-deliverable-review) по целому актуальному документу. Замечания исправляются до выдачи; у существенного сохраняемого плана кратко фиксируются метод проверки и её границы, включая различие самопроверки, автоматических проверок и независимого ревью. Применяются проверки, соответствующие содержанию; краткий ответ не требует развёрнутого плана.

Основной сценарий и границы разрешений находятся в [SKILL.md](SKILL.md). Подробные режимы и шаблон результата — в [harness-workflows.md](references/harness-workflows.md); готовые примеры запросов — в [upstream-guide.md](references/upstream-guide.md). Все 25 тематических справочников исходника сохранены. Сравнения провайдеров и исторические кейсы оставлены как справочный материал, требующий проверки перед практическим применением.

## Источник и обслуживание

Происхождение, commit и контрольные суммы исходных документов записаны в [provenance.json](provenance.json); лицензия — [LICENSE](LICENSE). Проверка upstream выполняется только по явному запросу пользователя на проверку версии или обновление скилла из upstream. При обычном вызове, начале задачи, последующих вопросах и локальных правках скилл использует проверенный снимок без автоматической проверки upstream. Точное правило находится в [SKILL.md](SKILL.md#freshness-and-self-update). Автоматическая замена инструкций отключена; обновление upstream требует отдельного запроса, повторного аудита и проверки. Проверка текущих API, моделей и других изменяемых внешних фактов остаётся отдельным требованием.

Канонический редактируемый исходник — `skills/agents-best-practices/` в Playground. При сопровождении следуйте `RULEBOOK.md` в корне проекта. Установка и обновление установленной копии выполняются из корня проекта:

```bash
bash skills/agents-best-practices/install-local.sh
```

Установщик заменяет только `${CODEX_HOME:-$HOME/.codex}/skills/agents-best-practices` локальным проверенным пакетом и не обращается к сети. Не клонируйте upstream поверх конвертации и не редактируйте установленную копию как второй исходник. `placement_mode` в provenance фиксирует исходную подготовку в scratch, а не текущий статус установки.

Секреты, локальная конфигурация, логи и runtime не нужны для чтения пакета. Реализация агента, запуск проверок или подключение сервиса — отдельная задача со своими доступами и артефактами.
